## 题意

给一个长度为 `n` 的数组，其中有一个元素出现次数**严格大于** `n / 2`（称为多数元素），题目保证它一定存在，返回这个元素。进阶要求：O(n) 时间、O(1) 空间。

```
输入：nums = [3,5,5,3,5,5,2]
输出：5
解释：n = 7，5 出现 4 次，4 > 3.5
```

```
输入：nums = [6,6,8]
输出：6
```

## 思路

直观做法：HashMap 计数，O(n) 时间 O(n) 空间；或者排序后取中间位置 `nums[n/2]`（多数元素占了一半以上，中位数一定是它），O(n log n)。想同时做到 O(n) 和 O(1)，用 **Boyer–Moore 投票算法**。

做法：维护一个"候选人" `cand` 和一个"票数" `count`。遍历数组：

- `count == 0` 时，把当前数设为新的候选人。
- 当前数等于 `cand`，`count++`；否则 `count--`。

遍历结束后的 `cand` 就是答案。

:::tip 为什么对
把 `count--` 理解成"候选人的一票和一个**不同的**数同归于尽"。每次抵消都从数组里拿走两个**不同**的数，其中最多有一个是多数元素 `m`，所以拿走之后 `m` 仍然占剩下部分的一半以上。更具体地：每当 `count` 回到 0，已经扫过的这一段恰好能两两配成不同的数，`m` 在这一段里最多占一半；既然 `m` 在全数组里超过一半，它在剩下的后缀里依然超过一半。最后一段 `count` 没归零，`count = cand 的次数 - 其他数的次数 > 0`，说明 `cand` 是最后这段的多数；一段里的多数元素是唯一的，所以 `cand == m`。
:::

用 `nums = [3,5,5,3,5,5,2]` 推演：

```
i  num  cand  count  说明
0  3    3     1      count 为 0，换候选
1  5    3     0      抵消
2  5    5     1      count 为 0，换候选
3  3    5     0      抵消
4  5    5     1      count 为 0，换候选
5  5    5     2
6  2    5     1      抵消
```

前 4 个数 `[3,5,5,3]` 两两抵消掉了，5 在其中恰好占一半；剩下的 `[5,5,2]` 里 5 仍是多数。

## Java 题解

```java
import java.util.*;

class Solution {
    public int majorityElement(int[] nums) {
        int cand = 0, count = 0;
        for (int x : nums) {
            if (count == 0) {
                // 之前的部分已经两两抵消干净，从当前数重新选候选人
                cand = x;
            }
            // 同一阵营加票，不同阵营同归于尽
            count += (x == cand) ? 1 : -1;
        }
        // 题目保证多数元素存在，否则需要再扫一遍验证 cand 的次数
        return cand;
    }
}
```

## 复杂度

- 时间 O(n)：一次遍历。
- 空间 O(1)：只有 `cand` 和 `count` 两个变量。

## 易错点

- 先判 `count == 0` 换候选，再加减票，顺序反了会让新候选人少一票。
- 算法只保证"**如果**存在多数元素，结果就是它"。如果题目不保证存在（比如面试官改题），必须再扫一遍统计 `cand` 的出现次数确认 `> n/2`，否则 `[1,2,3]` 也会返回 3。
- "多数"是严格大于 `n/2`，恰好一半（如 `[1,1,2,2]`）不算，投票结果没有意义。
- 最终的 `count` 不等于多数元素的出现次数，别拿它当频次用。

## 其他解法

排序后取中间：多数元素超过一半，无论它是最小还是最大，都会覆盖下标 `n/2`。代码最短，但 O(n log n)，并且会修改入参。

```java
import java.util.*;

class Solution {
    public int majorityElement(int[] nums) {
        // 超过一半的元素必然覆盖中间位置
        Arrays.sort(nums);
        return nums[nums.length / 2];
    }
}
```

- 进阶：出现次数超过 `n/3` 的元素最多两个（LeetCode 229），维护两个候选人即可，是投票算法的推广。
- 工程联系：流式数据里找"重度占比"的 key（例如热点 key 检测）时，Misra–Gries 算法就是投票算法推广到 k 个候选人，只用固定内存。

## 一句话记忆

候选人 + 票数，同则加、异则减、归零换人，过半的数一定活到最后。
