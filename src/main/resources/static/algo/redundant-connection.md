## 题意

一张无向图原本是一棵有 n 个节点（编号 1..n）的树，后来又多加了一条边，于是恰好出现一个环。给出全部 n 条边 `edges`，找出一条删掉后能让图重新变成树的边；如果有多条可选，返回在输入里**最靠后**的那条。

```
输入：edges = [[1,2],[2,3],[3,4],[1,4],[1,5]]
输出：[1,4]
解释：1-2-3-4-1 成环，环上的边里 [1,4] 在输入中最靠后
```

```
输入：edges = [[1,2],[1,3],[2,3]]
输出：[2,3]
```

## 思路

暴力：依次尝试删掉每条边（从后往前），每次用 DFS 检查剩下的图是否连通无环，O(n²)。

换个角度：按输入顺序一条条"加边"。加边前如果两个端点**已经连通**，这条边一加就成环，它就是多余的边。判断"两点是否已连通"并支持"合并"，正是并查集的本职。

为什么第一条合并失败的边就是"最靠后"的答案？环上的边中，前面的都能成功合并，只有把环闭合的那一条会失败，而闭合环的那条边一定是环上各边里在输入中最后出现的。

:::tip 关键点
按顺序 union，**第一条 union 失败（两端同根）的边**就是答案。节点编号从 1 开始，parent 数组开 n+1。
:::

用例子 1 推演：

```
边     find(u) find(v)  结果
[1,2]  1       2        合并
[2,3]  1       3        合并
[3,4]  1       4        合并
[1,4]  1       1        同根 -> 返回 [1,4]
```

## Java 题解

```java
import java.util.*;

class Solution {
    private int[] parent;

    public int[] findRedundantConnection(int[][] edges) {
        int n = edges.length; // 边数 = 节点数
        parent = new int[n + 1]; // 节点编号 1..n
        for (int i = 1; i <= n; i++) parent[i] = i;
        for (int[] e : edges) {
            int ru = find(e[0]), rv = find(e[1]);
            if (ru == rv) {
                return e; // 两端已连通，这条边会成环
            }
            parent[ru] = rv; // 合并两个集合
        }
        return new int[0]; // 题目保证有解
    }

    private int find(int x) {
        // 迭代式路径压缩（隔代压缩），避免深递归
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];
            x = parent[x];
        }
        return x;
    }
}
```

## 复杂度

- 时间 O(n · α(n))：每条边一次 find/union；这里只做了路径压缩，均摊也近似 O(log n) 以内，实际很快。
- 空间 O(n)：parent 数组。

## 易错点

- 数组开成 `n` 会越界，节点是 1..n。
- 合并时要写 `parent[ru] = rv`（根挂根），写成 `parent[e[0]] = e[1]` 会把原来的树结构截断，结果错误。
- 不要在全部合并完再找答案，发现同根就立刻返回，这样天然是"最靠后"的那条。
- 这是**无向图**版本；有向图版本（685 冗余连接 II）还要处理入度为 2 的情况，不能直接套。
