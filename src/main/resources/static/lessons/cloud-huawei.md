## 为什么要学

前四课讲的是与云厂商无关的概念：IAM、KMS、PKI、审计。这一课把它们**落在一个具体平台上**。选择华为云，是因为你在项目里已经用过 OBS，国内车企、IoT 平台也大量使用华为云；AWS 作为概念参照，因为大部分公开的云安全资料、靶场（如资源里的 CloudGoat）都是基于 AWS 的，学会“对照翻译”能让你两边都用得上。

云上安全配置问题有一个特点：**不需要任何漏洞利用技巧**。一个设成公开读的桶、一条放行 `0.0.0.0/0` 的 3306 安全组规则，任何人用浏览器或扫描器就能直接进来。你作为后端开发，往往就是那个创建桶、申请安全组规则的人，所以这些配置的正确性首先是你的责任（回忆 [[cloud-iam]] 里的共享责任模型）。

学完这一课，你能：正确使用 OBS 的桶策略、ACL 和预签名 URL，判断一个桶该不该公开；设计“公网 / 应用 / 数据”分层的 VPC 与安全组；知道 WAF、HSS 主机安全、CFW 云防火墙各自挡什么；用 CSA CCM 作为清单对自己的云环境做一次系统性自查。

:::tip 准确性约定
华为云的控制台菜单、策略 JSON 细节、SDK 类名会随版本变化。本课凡是标注“以文档为准”的地方，请对照资源中的 OBS / VPC 文档确认；AWS 的对照示例是精确语法，帮助你理解每个字段的含义。
:::

## 核心概念

### 1. OBS 桶策略、ACL、预签名 URL，公开桶的风险

控制“谁能访问 OBS 里的数据”有四种手段：

| 机制 | 挂在哪里 | 写法 | 适合场景 |
|---|---|---|---|
| IAM 策略 | IAM 用户 / 用户组 / 委托 | “我能访问哪些桶” | 本账号内的人和应用，首选 |
| 桶策略 | 桶上 | “谁能访问我、做什么、在什么条件下” | 跨账号授权、按前缀授权、公开某个目录、强制条件 |
| ACL | 桶或单个对象上 | 给账号或“所有人 / 匿名用户”授予读 / 写等粗粒度权限 | 兼容历史用法，一般不推荐新用 |
| 预签名 URL | 不挂在任何地方，是一条带签名的链接 | 由持有权限的一方签发，有过期时间 | 临时把某个私有对象给某个人下载 / 上传 |

**桶策略**的概念与 S3 桶策略相同（多了一个 `Principal` 字段，说明策略针对谁）。AWS S3 桶策略示例（精确语法）：只允许通过 HTTPS、并且只允许某个 VPC 终端节点访问：

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyOutsideVpce",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:*",
      "Resource": ["arn:aws:s3:::order-export", "arn:aws:s3:::order-export/*"],
      "Condition": { "StringNotEquals": { "aws:SourceVpce": "vpce-0example1234" } }
    },
    {
      "Sid": "DenyHttp",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:*",
      "Resource": ["arn:aws:s3:::order-export", "arn:aws:s3:::order-export/*"],
      "Condition": { "Bool": { "aws:SecureTransport": "false" } }
    }
  ]
}
```

OBS 控制台的桶策略页面提供“私有 / 公共读 / 公共读写”等模板，也支持自定义（可视化编辑或 JSON）。OBS 桶策略 JSON 中 Principal、Action、Resource 的具体写法与 S3 不完全相同，请以 OBS 文档“桶策略”章节的示例为准再编写。

**预签名 URL**（OBS 文档中常称为临时授权访问 / 临时 URL）：服务端用自己的 AK/SK 对“方法 + 桶 + 对象 + 过期时间”签名，生成一个任何人拿到都能在有效期内使用的 URL。适用于“App 用户下载自己的发票 PDF”“车机直传日志文件到 OBS”。AWS SDK v2 的写法（精确）：

```java
import software.amazon.awssdk.services.s3.model.GetObjectRequest;
import software.amazon.awssdk.services.s3.presigner.S3Presigner;
import software.amazon.awssdk.services.s3.presigner.model.GetObjectPresignRequest;

import java.net.URL;
import java.time.Duration;

public class PresignDemo {
    public static URL invoiceUrl(String key) {
        try (S3Presigner presigner = S3Presigner.create()) {
            GetObjectPresignRequest req = GetObjectPresignRequest.builder()
                    .signatureDuration(Duration.ofMinutes(5))
                    .getObjectRequest(GetObjectRequest.builder().bucket("invoice").key(key).build())
                    .build();
            return presigner.presignGetObject(req).url();
        }
    }
}
```

OBS Java SDK 中对应的是创建临时签名 URL 的接口（形如 `createTemporarySignature`，请以 OBS Java SDK 文档确认类名与参数）。使用要点：**有效期尽量短**（分钟级）；签发前先在业务上校验“这个用户能不能下载这个对象”（否则就是 [[web-access]] 里的 IDOR）；**不要把预签名 URL 打进日志**，它在有效期内等同于凭证。

**公开桶的风险**：公共读意味着任何人知道桶名和对象名就能下载；如果还允许匿名列举（ListBucket），攻击者连对象名都不用猜。桶名往往可以猜到（`公司名-backup`、`项目名-prod`），自动化扫描器会批量尝试。常见事故：数据库备份、日志、用户上传的身份证照片、含密钥的配置文件被放进了公开桶。公共读写则更糟：攻击者可以上传恶意文件、篡改你网站引用的 JS，或者把你的桶当免费网盘。

### 2. VPC、子网、安全组、网络 ACL

```
 Internet
    |
 [ EIP / ELB ] ---- WAF (L7)                                  公网入口只有这里
    |
 +--------------------- VPC 10.0.0.0/16 ----------------------+
 |  subnet-web 10.0.1.0/24   [ELB / Nginx]   sg-web           |   网络 ACL 可挂在子网上
 |        | 8080 (source = sg-web)                            |
 |  subnet-app 10.0.2.0/24   [ECS: Spring Boot]  sg-app       |   无 EIP，出网走 NAT
 |        | 3306/6379 (source = sg-app)                       |
 |  subnet-db  10.0.3.0/24   [RDS MySQL / Redis]  sg-db       |
 +------------------------------------------------------------+
    |
 [ NAT gateway ] -> Internet (outbound only)                  只出不进
```

| 概念 | 作用范围 | 特点 | 你该怎么用 |
|---|---|---|---|
| VPC | 一个隔离的私有网络 | 自己规划网段，不同 VPC 默认不通 | 生产、测试分不同 VPC |
| 子网 | VPC 内的一段地址 | 按层次划分：公网层、应用层、数据层 | 只有入口层的资源绑定公网 IP |
| 安全组 | 实例（网卡）级别 | **有状态**（放行的请求，其响应自动放行）；规则是“允许”列表 | 源地址尽量写**另一个安全组**而不是网段；22 / 3389 只对堡垒机或公司出口 IP 开放 |
| 网络 ACL | 子网级别 | 按优先级匹配的允许 / 拒绝规则，作为安全组之外的第二道防线 | 子网之间的粗粒度隔离，比如数据子网拒绝来自 web 子网的一切流量 |

AWS 的 NACL 是**无状态**的（出入方向都要显式放行，包括响应用的临时端口）；华为云网络 ACL 在状态处理、默认规则上的具体行为请以 VPC 文档为准，配置前务必确认，否则容易把返回流量挡掉。

最常见的错误配置：安全组入方向 `0.0.0.0/0` 放行 22、3306、6379、8080（Spring Boot Actuator）、18083（EMQX Dashboard 默认端口）；ECS 直接绑 EIP 而不是放在 ELB 后面；测试环境和生产环境在同一个 VPC 且互通。

### 3. WAF、主机安全、云防火墙

三者分别守在不同的层次，互相补充：

| 服务 | 位置 | 挡什么 | 与你学过的内容的关系 |
|---|---|---|---|
| WAF（Web 应用防火墙） | HTTP 入口（ELB / 域名前） | SQL 注入、XSS、命令注入、扫描器、恶意 Bot；CC 攻击（按频率限制）；IP / 地域黑白名单；精准访问控制规则 | [[web-sqli]]、[[web-xss]] 的“虚拟补丁”；但不能替代代码修复 |
| HSS 主机安全 | 每台 ECS 上的 agent | 漏洞与基线检查（弱口令、危险配置）、暴力破解检测、异常登录、Webshell、恶意进程、挖矿、勒索 | [[linux-ssh]]、[[linux-perm]] 的自动化体检和入侵检测 |
| CFW 云防火墙 | 互联网边界、VPC 之间 | 基于五元组和域名的访问控制、入侵防御（IPS）、东西向流量控制、流量日志 | 弥补安全组“看不到应用层、难以统一管理”的不足；限制出站可以挡 SSRF / 木马回连 |

一个用来理解分工的思路：**WAF 看请求内容，CFW 看连接，HSS 看主机内部**。例如 Log4Shell 类攻击，WAF 可能在请求中识别到恶意字符串；如果漏过了，CFW 的出站控制可能阻止服务器连向攻击者的 LDAP 服务器；如果还是漏过了，HSS 可能发现 Java 进程拉起了异常的子进程。

### 4. CSA 云控制矩阵（CCM）作为检查清单

CSA 的 **Cloud Controls Matrix（CCM）** 是一套云安全控制框架。v4 版本分为 17 个领域，例如：IAM（身份与访问管理）、CEK（密码学、加密与密钥管理）、DSP（数据安全与隐私生命周期管理）、IVS（基础设施与虚拟化安全）、LOG（日志与监控）、SEF（安全事件管理、电子取证与云取证）、TVM（威胁与漏洞管理）、CCC（变更控制与配置管理）、AIS（应用与接口安全）、BCR（业务连续性与运营韧性）等。每个控制项还标注了云厂商和客户各自的责任。

对个人学习者，CCM 的价值不在于“合规”，而在于**提供一份不遗漏的清单**：它逼你逐个领域问“我这里有没有做”。下面的练习会按领域挑出与本阶段相关的检查项。完整的矩阵（电子表格）可从资源中的 CSA 页面获取。

## 动手实践

### 练习：用华为云搭一套 VPC + ECS + OBS，并按 CCM 做一遍自查

按量付费、用最小规格，做完及时释放，避免产生费用。

**第 1 步：网络。** 创建 VPC `lab-vpc`（10.0.0.0/16），两个子网 `subnet-web`（10.0.1.0/24）、`subnet-app`（10.0.2.0/24）。创建三个安全组：

| 安全组 | 入方向规则 | 说明 |
|---|---|---|
| sg-bastion | TCP 22，源 = 你的公网 IP/32 | 只有你能 SSH 到跳板机 |
| sg-web | TCP 443，源 = 0.0.0.0/0 | 对外只开 HTTPS |
| sg-app | TCP 8080，源 = sg-web；TCP 22，源 = sg-bastion | 应用不直接暴露，SSH 只能经跳板机 |

**第 2 步：主机。** 在 `subnet-app` 创建一台 ECS（不绑 EIP，绑定 sg-app，使用密钥对登录而不是密码），在 `subnet-web` 创建一台带 EIP 的小规格 ECS 作跳板 / Nginx（绑定 sg-web + sg-bastion）。如需让应用机访问公网（下载依赖），配置 NAT 网关 SNAT。开启 HSS 主机安全（基础防护即可）。

**第 3 步：OBS + 委托。** 创建私有桶 `lab-order-export-<随机后缀>`，开启默认加密（使用 KMS，见 [[cloud-secrets]]）。在 IAM 中创建一个“云服务 → ECS”类型的委托，授予 [[cloud-iam]] 练习中的“只读某前缀”自定义策略，把委托绑定到应用机 ECS。

**第 4 步：验证网络暴露面。** 在你自己的电脑上扫描跳板机 EIP（只扫描你自己的资源）：

```bash
nmap -Pn -p 22,443,3306,6379,8080 <跳板机EIP>
```

```
PORT     STATE    SERVICE
22/tcp   open     ssh
443/tcp  closed   https
3306/tcp filtered mysql
6379/tcp filtered redis
8080/tcp filtered http-proxy
```

**解读**：`filtered` 表示包被安全组静默丢弃，这是我们想要的；`open` 的 22 只因为源 IP 是你自己才放行，换一个网络（手机热点）再扫，22 也应该是 `filtered`；443 `closed` 表示安全组放行了但机器上还没有服务在监听。如果 3306 出现 `open`，立即检查安全组。

**第 5 步：验证 OBS 不可匿名访问。**

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://<桶名>.obs.<区域>.myhuaweicloud.com/reports/a.csv
curl -s -o /dev/null -w '%{http_code}\n' "https://<桶名>.obs.<区域>.myhuaweicloud.com/?max-keys=5"
```

两条都应该返回 `403`。第二条如果返回 `200` 且内容是对象列表，说明桶允许匿名列举，这是最危险的配置。

**第 6 步：验证委托凭证。** 登录应用机后查看元数据服务（华为云 ECS 兼容 OpenStack 元数据路径；委托临时凭证的具体路径以 ECS 文档为准）：

```bash
curl -s http://169.254.169.254/openstack/latest/meta_data.json | head -c 300
```

能看到实例 ID、可用区等元数据，说明元数据服务可达。这也提醒你：这台机器上的任何 SSRF 都能访问这个地址（回顾 Lab 05 与 [[web-ssrf]]）。然后用 OBS SDK 或 obsutil 在**不配置 AK/SK** 的情况下，通过委托凭证读取 `reports/` 下的对象（应成功）、写入对象（应返回 403）。

**第 7 步：按 CCM 领域自查。** 把检查结果填成表格，每一项都要有“证据”（截图或命令输出）：

| CCM 领域 | 检查项 | 本实验的证据 |
|---|---|---|
| IAM | 根账号开 MFA、不用根账号的 AK；应用用委托、策略最小权限 | IAM 用户列表、委托策略 JSON、第 6 步的 403 |
| CEK | OBS 默认加密使用 KMS；密钥可轮换、有访问审计 | 桶加密配置、KMS 密钥详情 |
| DSP | 桶私有、无匿名列举；敏感数据识别和分级 | 第 5 步两个 403 |
| IVS | 分层子网、安全组最小开放、应用机无公网 IP | 安全组规则截图、第 4 步 nmap 结果 |
| LOG | CTS 追踪器开启并转储到独立桶；关键操作有告警 | 追踪器配置、一条测试告警（见 [[cloud-detect]]） |
| TVM | HSS 开启，漏洞与基线检查无高危项 | HSS 检查报告 |
| SEF | 有 AK 泄露、主机被入侵的响应预案 | 预案文档 |
| CCC | 安全组、桶策略等变更有记录和审批 | CTS 中的变更事件 |

**解读**：自查的产出不是“全部打勾”，而是一个**差距清单**。例如个人实验账号往往没有独立审计账号、没有预案，这些就是记录下来、以后在工作中推动的改进项。

## 攻击者视角

> 本课涉及的攻击手法只用于你自己的云账号或已获授权的目标。

- **枚举公开桶**：根据公司名、App 名、域名生成候选桶名，批量请求 `https://<桶名>.obs.<区域>.myhuaweicloud.com/`。返回 `NoSuchBucket` 说明不存在，`AccessDenied` 说明存在但私有（桶名本身也泄露了信息），返回对象列表就是中了大奖。前端 JS、App 安装包里硬编码的桶域名也是常见线索。
- **利用预签名 URL**：从日志、Referer、分享链接中捡到长期有效的预签名 URL；或者利用“签发前没做权限校验”的接口，把 `key` 参数改成别人的发票路径，得到别人文件的合法 URL。
- **扫描暴露端口**：全网扫描 22、3306、6379、9200、18083、8080 等端口，找弱口令或未授权访问（Redis 未授权写 SSH 公钥、Elasticsearch 未授权读数据、Actuator 泄露配置）。
- **从一台主机横向移动**：拿下一台 ECS 后，读取元数据服务的委托凭证，调用云 API；在 VPC 内扫描其他子网，利用安全组“同 VPC 全放通”的宽松规则直连数据库。
- **绕过 WAF**：编码变形、分块传输、使用 WAF 规则未覆盖的参数位置（JSON 体、Header）；或直接找到源站 IP 绕过 WAF 访问（所以源站安全组应只允许 WAF / ELB 回源地址）。

## 防御与最佳实践

- **OBS**：默认私有；用 IAM 策略和委托授权本账号应用；跨账号用桶策略；少用 ACL；预签名 URL 短有效期、签发前做业务鉴权、不进日志；开启默认加密、版本控制、访问日志；敏感桶用桶策略强制 HTTPS 和来源限制。
- **公开内容与私有内容分桶**：静态资源放专门的公开桶（最好前面挂 CDN），其他桶一律私有，并用定期检查确认“公开桶清单”没有变化。
- **网络**：分层子网；应用和数据层不绑公网 IP；安全组源地址用安全组引用；管理端口只对堡垒机开放；生产、测试 VPC 隔离；源站只允许 WAF / ELB 回源。
- **纵深**：入口 WAF，边界和东西向用 CFW（含出站控制），每台主机开 HSS，所有 API 操作进 CTS。
- **持续自查**：以 CCM 为清单定期复查；把安全组、桶策略纳入基础设施即代码（如 Terraform）和代码评审，而不是在控制台随手改。

**问题：“桶公开读”在什么情况下是合理的？如何确保只有这些桶是公开的？**

合理的情况：内容**本来就打算让所有人看到**，且不含任何个人信息或内部信息。例如网站 / 小程序的静态资源（JS、CSS、公开图片）、公开下载的 App 安装包和固件（车机 OTA 包如果公开下载，应另有签名校验保证完整性）、公开文档。即使如此，也应只开“公共读对象”，**不开匿名列举**，更不开公共写；最好通过 CDN 对外提供。

确保只有这些桶公开：

1. **命名与分离**：公开内容放专门的桶（如 `xxx-public-static`），其他桶一律私有，禁止把公开和私有内容混在一个桶里。
2. **权限收口**：只有少数管理员有修改桶策略 / ACL 的权限，普通开发者的 IAM 策略中不包含这类操作。
3. **检测**：CTS 中对“修改桶策略 / 修改 ACL”事件告警；定期用脚本遍历所有桶，检查策略和 ACL 中是否出现匿名 / 所有人的授权，与“公开桶白名单”比对。
4. **外部验证**：从外网匿名 `curl` 每个桶的列举接口和一个示例对象，结果应符合预期（第 5 步的做法）。

## 常见误区

- **“桶名很长很随机，别人猜不到”**：桶名会出现在前端代码、App 包、日志、Referer 中，隐蔽不等于安全。
- **“预签名 URL 设置 7 天比较方便”**：有效期内任何拿到链接的人都能用，应尽量短。
- **“安全组放行同 VPC 所有流量没关系”**：一台机器沦陷，整个 VPC 都暴露；应按层次和端口最小放行。
- **“买了 WAF 就不用修漏洞”**：WAF 是缓解措施，能被绕过，代码层修复（参数化查询、输出编码）才是根本。
- **“开了 HSS 就不用管主机”**：HSS 报出的弱口令、漏洞需要你去修；告警没人处理就没有意义。
- **“CCM 是大公司做合规用的”**：把它当作清单，对个人项目同样能快速发现盲区。

## 自测

:::details 1. IAM 策略、桶策略、ACL、预签名 URL 各适合什么场景？
IAM 策略：授权本账号内的用户和应用（委托），首选。桶策略：跨账号授权、按前缀授权、对整个桶强制条件（HTTPS、来源）。ACL：粗粒度的历史机制，一般不推荐新用。预签名 URL：临时把某个私有对象的下载 / 上传能力交给特定的人，有效期短。
:::

:::details 2. 使用预签名 URL 时要注意哪三件事？
签发前做业务鉴权（防 IDOR）；有效期尽量短；不要把 URL 记录进日志或泄露到 Referer 中，它在有效期内等同于凭证。
:::

:::details 3. 安全组和网络 ACL 的主要区别是什么？
安全组作用于实例（网卡）级别，有状态，只写允许规则，是主要的访问控制手段；网络 ACL 作用于子网级别，按优先级匹配允许 / 拒绝规则，是第二道防线。AWS 的 NACL 是无状态的；华为云网络 ACL 的状态行为以文档为准。
:::

:::details 4. 为什么安全组的源地址推荐写“另一个安全组”而不是网段？
网段会包含该网段内所有机器，包括以后新加入的、不相关的机器；引用安全组表示“只有绑定了该安全组的实例才能访问”，与实例的实际角色绑定，扩缩容时也不需要修改规则。
:::

:::details 5. WAF、HSS、CFW 分别在哪一层防护？各举一个它能发现的例子。
WAF 在 HTTP 入口看请求内容，例如 SQL 注入 payload；CFW 在网络边界和 VPC 之间看连接，例如服务器向陌生地址的出站连接；HSS 在主机内部，例如 SSH 暴力破解、挖矿进程、Webshell。
:::

:::details 6. “桶公开读”在什么情况下是合理的？如何确保只有这些桶是公开的？
内容本来就要对所有人公开且不含敏感信息时，如静态资源、公开安装包和文档，且只开对象读、不开匿名列举和写。确保方法：公开内容单独建桶、修改桶策略 / ACL 的权限收口、CTS 对策略变更告警、定期脚本比对公开桶白名单、从外网匿名验证。
:::

:::details 7. CSA CCM 在个人学习和项目自查中怎么用？
把它当成按领域组织的检查清单（IAM、CEK、DSP、IVS、LOG、TVM、SEF 等），对每个领域列出检查项并附上证据，产出差距清单和改进计划，而不是追求全部打勾。
:::

## 一句话总结

在华为云上：桶默认私有、授权走 IAM 委托和桶策略、分享用短期预签名 URL；网络分层、安全组最小开放；WAF、CFW、HSS 分层纵深；最后用 CCM 当清单持续自查。
